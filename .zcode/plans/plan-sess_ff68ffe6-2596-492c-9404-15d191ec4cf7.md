## Objective

1. **Local/Hosted deployment mode** — auth, API-key DB, rate limiting, and search cooldown become *conditional security surfaces* that activate only in **hosted mode**. In **local mode** (default, flag unset) the engine runs keyless, freely, with no gating middleware — per global doctrine `50-security-runtime: Conditional Security Surfaces` and the user's request.
2. **Remediate every "lacking point"** from the prior audit, in both JS and Rust runtimes (user chose **JS + Rust both**, **clean-slate** key migration).
3. **Comply with `~/.codex/AGENTS.md`** doctrine, and create a repo-level `.codex/agents.md` encoding this product's contracts.

## The gate (capability-named, doctrine `32-configuration`)

A single config owner computes `mode ∈ {local, hosted}`:
- `INSECT_HOSTED=1` → hosted.
- `NODE_ENV=production` → also implies hosted (safety: you cannot run prod keyless by accident).
- Otherwise → local (default).

| Behavior | Local mode | Hosted mode |
|---|---|---|
| `/api/engine`, `/api/youtube/transcript` | No auth, no rate limit, no cooldown — pass-through | Full key validation + rate limit + 6s search cooldown |
| `/api/keys/*` admin routes | **Disabled** (404) | Require real `ADMIN_KEY` (no default secret) |
| `/health` | `{status,service,version,uptime}` + observability (own machine) | Minimal liveness only |
| `/health/observability` | Open | Admin-auth required |
| Engine concurrency | Free / async / unqueued | Per-key bounded |

## Remediation map (every lacking point → fix)

| # | Lacking point | Fix |
|---|---|---|
| — | Auth only needed in prod/hosted | **Local/Hosted mode gate** (above) |
| 1 | API keys stored in plaintext | New schema: `key_hash` (sha-256) PRIMARY KEY; plaintext `sk_…` returned **once** at create, never stored |
| 2 | No timing-safe comparison | `crypto.timingSafeEqual` for admin secret (JS + Rust); key lookup now compares hashes of high-entropy secrets |
| 3 | Hard-coded default admin secret | **Hosted mode requires `ADMIN_KEY`** — fail-fast startup error if unset. `admin_change_me` default removed entirely |
| 4 | Per-key limits bypassable; admin minting unbounded | Real admin auth (no default) closes the practical hole; add a lightweight in-memory per-IP admin-route limiter (hosted only, 10/min) |
| 5 | `/health` leaks info unauthenticated | Split: `/health` = minimal liveness always; `/health/observability` = admin-gated (hosted) or open (local) |
| 6 | Masking leaks ~30% of secret | Hashed storage means plaintext is never in DB; `listKeys` shows `keyHash` prefix + label, never a secret prefix |
| 7 | Observability in-memory only | Document `/health/observability` as the scrape surface; emit snapshot to the logging owner on shutdown + periodic sample |
| 8 | Regex recompilation (Rust) | `std::sync::LazyLock` for all compiled regexes in `formatters.rs` / `transcript.rs` |
| 9 | Single-threaded DB (Rust) | Document as hosted-throughput residual (out of safe scope without benchmarking); local mode doesn't use the DB |
| 10 | Windows-centric browser discovery (Rust) | Add macOS (`/Applications/Google Chrome.app/...`) + Linux (`/usr/bin/google-chrome`, chromium) paths to `detect_browser_path` |
| 11a | Rust user-agent version mismatch | Use `env!("CARGO_PKG_VERSION")` instead of hardcoded `"insect-rs/0.1.0"` |
| 11b | Duplicate MCP tools (`engine-search` ≈ `search-web`) | Collapse into one `search-web` tool using the `query` field (doctrine `95-anti-patterns`: no parallel systems) |
| 11c | Bearer-header ambiguity | Admin auth becomes **header-only** (`x-admin-key`); API keys keep `Bearer`. No more shared parsing |

## Honest residuals (documented, not silently skipped)
- **Rust DB concurrency (point 9):** `Mutex<Connection>` stays; local mode avoids it; hosted high-throughput pooling is a separate benchmarked effort.
